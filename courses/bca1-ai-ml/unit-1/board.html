Warm-up

The principal says: “Find the topper.”

Sounds simple. Now write down every question you would need to ask before a computer could do it.

Some answers change the program completely:

  • Topper in one subject or overall?
  • What if two students tie?
  • Are absent students included?

A computer never guesses what you meant.
Problem solving starts before the code.

Problem vs instance

Problem and problem instance

Problem = a general question about inputs, and what the answer must be.
Given marks m₁, m₂, …, mₙ (n ≥ 1), find the largest.
Instance = the problem with actual input values.
[72, 85, 64] → 85
[40] → 40
[90, 90, 12] → 90

📝 Problem = the blank form
🧾 Instance = one filled-in form

One problem → infinitely many instances.

An algorithm solves the problem, so it must work for every valid instance, not just the one in your notebook.

Generalization · maths

Generalization and special cases

Specific: 1 + 2 + … + 100
(1+100) + (2+99) + … + (50+51)
= 50 × 101 = 5050
General: 1 + 2 + … + n = n(n + 1) / 2
More general (AP): a, a+d, …, n terms
S = n/2 × [2a + (n − 1)d]

Generalize: solve the whole family, not one case. One program then serves every input.

Special cases: the unusual instances you must check:

  • n = 1 → 1(2)/2 = 1 ✔
  • n = 0 → 0 (empty sum) ✔
  • an empty list, all values equal, a tie, negative input

Problem-solving steps

Pólya’s four steps of problem solving

1 Understand: What is given? What is asked? Any conditions?

2 Plan: Seen a similar problem? Break it into parts. Write the algorithm.

3 Execute: Carry out the plan step by step; write and run the code.

4 Review: Check the result with tests. Faster way? Can it be reused?

George Pólya, How to Solve It, 1945

Algorithm development

What makes an algorithm?

A finite sequence of precise steps that solves every instance of a problem.

  1. Finite: ends after a limited number of steps
  2. Definite: each step is exact, no guessing
  3. Input: zero or more inputs
  4. Output: at least one output
  5. Effective: each step is basic enough to do by hand
Algorithm FindMax
Step 1: Read n and m[1..n]
Step 2: max ← m[1]
Step 3: For i ← 2 to n
        If m[i] > max then max ← m[i]
Step 4: Print max
Step 5: Stop

Correctness

Is it correct?

Pass isum afterInvariant: sum = 1+…+i
start0empty sum = 0 ✔

361+2+3 ✔
4101+2+3+4 = 4·5/2 ✔
Partial correctness: if it stops, the answer is right (invariant + post-condition).
Termination: it always stops (i grows by 1 up to n).
Total correctness = both. Testing helps, but “testing shows the presence, not the absence, of bugs” (Dijkstra).
