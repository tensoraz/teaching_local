Over / underfitting

Underfitting, overfitting and the sweet spot

Underfitting (high bias): too simple. Bad on train and test. Depth 1: AUC 0.58 / 0.55.
Overfitting (high variance): memorises noise. Train ≫ test. No depth limit: 1.00 / 0.58.
Just right: depth 4, CV AUC 0.658. Choose it with cross-validation.

Ensembles · maths

Why many models beat one

5 independent models, each 70% right; majority vote:
P(≥ 3 right) = C(5,3)·0.7³·0.3² + C(5,4)·0.7⁴·0.3 + 0.7⁵
= 0.309 + 0.360 + 0.168 = 0.837
25 such models → 0.983
The catch: it only works if the models make different mistakes. 25 identical trees = 1 tree.
Bagging / random forest: diversity from random rows + random features, trees in parallel → lower variance
Boosting: each new model fixes the previous ones’ errors, in sequence → lower bias

Boosting · maths

Boosting: learn from the mistakes

AdaBoost

weak learner error ε = 0.30
vote weight α = ½ ln((1 − ε)/ε) = ½ ln(2.33) = 0.424
wrong rows × eα = 1.53 · right rows × e−α = 0.65
then normalise → next learner focuses on hard cases

Over / underfitting

Avoiding overfitting and underfitting

Overfitting? (train ≫ test)

  • Simpler model: limit depth, raise min leaf size
  • Regularisation (L1/L2, smaller C)
  • More training data
  • Fewer, better features (Unit 2)
  • Bagging / random forest
  • Early stopping in boosting
  • Prune trees

Underfitting? (both low)

  • More flexible model (deeper tree, boosting)
  • Better features (derived features, interactions)
  • Less regularisation
  • Train longer (more boosting rounds)
Always: choose with cross-validation, test once.
