Linear regression · maths

Simple linear regression: least squares

ŷ = a + b·x · choose a, b to minimise Σ(y − ŷ)²
b = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)² · a = ȳ − b·x̄
Age x12345
Price y (₹ lakh)8.07.16.55.44.9
x̄ = 3, ȳ = 6.38 · Σdx·dy = −7.90 · Σdx² = 10
b = −0.79 · a = 6.38 + 0.79 × 3 = 8.75
price = 8.75 − 0.79 × age
SSE = Σ(y − ŷ)² = 0.067 · SST = Σ(y − ȳ)² = 6.308
R² = 1 − SSE/SST = 0.989

Regression · maths

How good is a regression?

R² = 1 − SSE / SST
Adjusted R² = 1 − (1 − R²)(n − 1)/(n − k − 1)
= 1 − 0.043 × 839/830 = 0.956
RMSE = √(Σ(y − ŷ)²/n) = 0.885
MAE = Σ|y − ŷ|/n = 0.697 (₹ lakh)

Assumptions (LINE + one)

  • Linear relationship
  • Independent errors
  • Normal-ish residuals
  • Equal spread of residuals
  • No strong multicollinearity (Unit 2: r = 0.91!)

Check with a residual plot: a shapeless cloud around 0.

Decision tree · maths

Decision tree: split to reduce impurity

Gini = 1 − Σ pᵢ²
Root: 238 churn / 1,050 → p = 0.227
1 − (0.227² + 0.773²) = 0.351
Split: support_calls ≤ 2.5
left 907 → 0.313 · right 143 → 0.491
weighted = (907×0.313 + 143×0.491)/1050
= 0.337 → gain 0.014

Entropy = −Σ pᵢ log₂ pᵢ is the alternative (ID3/C4.5).

Riskiest leaf: calls ≥ 3 AND tenure ≤ 37 AND no autopay → 51 of 85 churned = 60%
Safest: calls ≥ 3 AND tenure > 37 AND no autopay → 0 of 15
Importance: tenure 0.43 · calls 0.42 · autopay 0.15 · others 0
Decision tree

Trees: readable rules, but they overfit

✔ Strengths

  • Rules a manager can read
  • No scaling needed
  • Handles non-linear patterns and interactions
  • Mixes numeric and categorical inputs

✘ Weaknesses

  • Deep trees memorise the training data
  • Unstable: small data changes → different tree
  • Step-shaped predictions

Control with max_depth, min_samples_leaf, pruning

P(C | E) = P(E | C) · P(C) / P(E)
naïve: P(E | C) = Π P(eᵢ | C)

Process

The model-building process

  1. Define the target and the business metric
  2. Choose candidate features (Unit 2)
  3. Split: train / (validation) / test
  4. Fit preprocessing on train only: imputation, scaling, encoding
  5. Train candidate models
  6. Tune on validation data (Unit 4)
  7. Evaluate once on the test set
  8. Interpret, document, deploy (Unit 5)
Data leakage: information from the test set (or from the future) sneaks into training, e.g. scaling with the mean of ALL rows, or a feature like “cancellation_date”. Scores look great, real performance is worse.
Training & testing

Training and testing datasets

Stratify on the target: train 22.7% churn, test 22.7% churn
random_state = 42: the same split every run, so results can be reproduced
Validation set (e.g. 60/20/20) for tuning; the test set is used once at the end
